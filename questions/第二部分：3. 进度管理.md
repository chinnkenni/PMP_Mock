# 答案与解析

# 1、答案：C

解析：里程碑没有历时，不需要资源。

# 2、答案：D

解析：基于项目实际情况和项目需求，进度管理计划可以是正式的或非正式的，可以是简略的或非常详细的。

# 3、答案：B

解析：提前量和滞后量的使用不能替代进度逻辑关系，而且持续时间估算中不包括任何提前量或滞后量

# 4、答案：D

解析：见《PMBOK指南》资源平衡、资源平滑定义。

# 5、答案：A

解析：题目中的干系人认为这是一种不可颠倒、串行的逻辑关系。

# 6、答案：D

解析：在••开始•••周前开始"是开始到开始关系，提前量是减号。

# 7、答案：A

解析：假设情景分析用于评估不利条件下项目进度的可行性。这是对“如果情景”X’所代表的情况发生了怎么办？“这一问题的分析，用于制定应急和响应计划，以减轻不利条件的影响。

# 8、答案：C

解析：燃尽图分析与理想燃尽图的偏差。可使用预测趋势线来预测迭代结束时可能出现的偏差，以及在迭代期间应该采取的合理行动。

# 9、答案：C

解析：正向分析计算了活动的最早开始和最早结束时间，反向分析计算的是活动的最晚开始和最晚结束时间，是典型的关键路径法，目的是通过计算活动的总浮动时间，以及分析在不考虑资源限制的情况下项目的关键路径。

# 10、答案：A

解析：快速跟进会增加风险，且只能针对软逻辑关系。由于是低风险项目，适当增加风险也没有关系，不会超出风险承受力。

# 11、答案：D

解析：可能需要，但不是必然要这样做的。从综合的角度来看，“尽快完工”不一定是好事。

# 12、答案：B

解析：在进度压缩之后，关键路径改变是可能的或者出现新的关键路径。

# 13、答案：B

解析：这是假设情景分析的典型假设问题。

# 14、答案：A

解析：参见 PMBOK 制定进度计划工具。

# 15、答案：D

解析：项目的关键路径是具有最少浮动量的一系列活动，通常为零（灵活性）。

# 16、答案：B

解析：文件编写结束前 3天就开始后续的工作，这是带时间提前量的完成到开始关系。

# 17、答案：D

解析：编程和质量保证活动是一种开始到开始的逻辑关系，同时有15天的滞后，用“+15天” 表示。

# 18、答案：D

解析：在项目日历中列出可用于开展项目活动的时间段以及不可用于开展项目活动的时间段。

# 19、答案：D

解析：最有可能的、乐观的和悲观的是通常在多点估计过程中使用的三点估算。

# 20、答案：C

解析：进度计划偏差为零，即项目 PV=EV，里程碑事件在关键路线上，里程碑事件延迟，说明项目关键路径状态报告未能准确反应进度的状况。

# 21、答案：B

解析：估算活动持续时间可能会用到类比估算、参数、三点、自下而上等工具。

# 22、答案：B

解析：平均时间是三点法估算所计算出的结果。

# 23、答案：A

解析：关键路径活动延迟，先分析对进度的影响。

# 24、答案：B
